# 客户端兼容

Gatehouse 使用标准 SSH 协议。临时用户名和密码让第三方客户端无需实现专用登录插件；客户端发出的每个请求仍需符合已签发的申请。

## 支持范围

| 使用方式 | 申请模式 | 约束与说明 |
| --- | --- | --- |
| OpenSSH / 交互终端 | `shell` | PTY 必须符合 `require`、`allow` 或 `forbid` |
| 执行一条固定命令 | `exec` | 实际命令与申请字符串精确一致，包括空白 |
| SFTP 文件管理 | `sftp` | 限制根目录、文件操作和连接/通道配额 |
| 现代 OpenSSH SCP | `scp` | 走 SFTP 协议；不支持 legacy `scp -O` |
| 本地 TCP 转发 | `tcp` | 固定数字 IP、端口和路由；通常使用输出的 `-L` 命令 |
| 同时打开终端和文件面板 | `shell` + `sftp` | 需要足够连接与通道配额；不是所有工具都已逐一验收 |

远程开发工具经常自动探测系统、执行额外命令、创建多条连接或转发。不能仅凭“支持 SSH”判断整个远程开发流程兼容，必须核对工具的真实请求。项目未给出完整客户端版本认证清单。

## 如何填写连接信息

从申请结果复制以下字段，不使用后端服务器地址代替入口：

| 客户端字段 | 填写内容 |
| --- | --- |
| 主机 | 输出的堡垒机入口地址 |
| 端口 | 输出的堡垒机 SSH 端口，默认 2222 |
| 用户名 | 本次申请生成的 `ghp_…` 用户名 |
| 认证方式 | 密码 |
| 密码 | 本次申请生成的随机密码 |
| 主机指纹 | 与申请输出及可信管理员渠道核对 |

普通用户用公钥登录菜单；新临时连接使用上述密码。不能把菜单登录用户名 `admin` 和临时密码拼在一起使用。

## 终端加文件面板

部分客户端在连接后自动打开 SFTP 面板，或者为文件操作另建连接。只申请一次 shell 时，这些操作可能失败。若确实需要，可按[使用指南](usage.md)申请 `shell` 与 `sftp`，并显式配置 `total`、`concurrent`、`sessions`、`channels` 和 `reconnect`。

多连接和重连还需要相应授权。先用最小 OpenSSH 连接确认链路，再逐步开启客户端的额外功能，避免把协议限制误认为密码错误。

## TCP 转发的边界

默认 `tcp_route` 经目标 SSH 到达目标侧端点；`tcp_route=jump` 由堡垒机直拨，需要额外授权。端点必须是申请中的数字地址和端口。

不支持反向 `-R`、任意透明 ProxyJump、agent、X11 或 Unix socket 转发。服务端可校验实际目的端点，看不到客户端本地监听地址，也不能可靠区分客户端用 `-L` 还是 `-D` 表达意图。

## 连接立即被关闭

先检查申请有效期、次数和实时授权，再检查模式、PTY、自动 exec、环境变量、文件根和通道配额。实际请求越过申请边界会被拒绝；应调整明确需要的申请和授权，而不是关闭服务端核验。更多错误见[故障排查](troubleshooting.md)。
